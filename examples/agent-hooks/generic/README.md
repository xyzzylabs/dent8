# Generic shell adapter

Three tiny POSIX scripts that wire dent8's shared fact base into **any** agent framework that
can run a command — no provider-specific hook schema, no MCP client required. They mirror the
hardened Claude Code hooks in [`../../../.claude/settings.json`](../../../.claude/settings.json):
each script no-ops silently when `dent8` is missing and sources `.dent8/env` when present.

For a fully-wired, native reference see the [Claude Code profile](../claude-code/) — its
`SessionStart`/`SessionEnd` hooks are exactly `dent8 context` and `dent8 capture`, which is
what these scripts expose to everything else.

## The three primitives

| Script | dent8 surface | When to run |
| --- | --- | --- |
| [`pre-session.sh`](pre-session.sh) | `dent8 context` | Session start — prepend its stdout to the agent's prompt / system message. |
| [`post-session.sh`](post-session.sh) | `dent8 capture … --consume --keep-failed` | Session end — drain the agent's queued proposals through the firewall. |
| [`sync-agents-md.sh`](sync-agents-md.sh) | `dent8 context` into a managed block | Whenever facts change — refresh a static instructions file (`AGENTS.md`). |

Every script starts with the same two hardening lines from the live Claude Code hooks:

```sh
command -v dent8 >/dev/null 2>&1 || exit 0
if [ -f .dent8/env ]; then set -a; . .dent8/env; set +a; fi
```

The first is a fail-open missing-binary guard (a host without dent8 sees no error). The second
loads `.dent8/env` (`DENT8_LOG`, `DENT8_AUTHORITY`, …) so the scripts work from any subdirectory
of the repo.

### `pre-session.sh` — context in

Emits the believed-facts context pack to stdout. Pass-through flags reach `dent8 context`:

```sh
./pre-session.sh                # markdown pack (default)
./pre-session.sh -o json        # machine-readable
./pre-session.sh --kind repo    # only repo:* facts
```

This is the universal "prepend to your prompt / system message" primitive. A run against a
store with two facts (verified locally):

```text
$ ./pre-session.sh
## Project facts (dent8)

<!-- generated by `dent8 context` at 1783602099865; regenerate instead of hand-editing -->

Currently-believed facts from the dent8 memory firewall. Each carries its authority and source; verify one with `dent8 explain <subject> <predicate>`.

### repo:demo

- `build_command` = "cargo build --release"  (authority: high, source: source:human, ref: dent8://repo/demo/build_command)
- `test_command` = "cargo test --workspace"  (authority: medium, source: source:ci, ref: dent8://repo/demo/test_command)
```

### `post-session.sh` — capture out

Flushes the agent's proposal queue through the same authority/policy/content-check funnel as
every other dent8 write. The agent (or a wrapper) appends JSON-line proposals to the queue
during the session; this drains it at the end. `--consume` truncates the file so it is not
replayed next session; `--keep-failed` retains rejected/malformed lines (accepted lines are
removed) for inspection or retry.

Override the queue path with `DENT8_PROPOSALS` (default `.dent8/proposals.jsonl`, matching the
live Claude Code `SessionEnd` hook). A verified run where one proposal is accepted and one
malformed line is kept for retry:

```text
$ cat .dent8/proposals.jsonl
{"subject":"repo:demo","predicate":"ci_runner","value":"ubuntu-latest","authority":"medium","source":"source:ci"}
this line is not valid json

$ ./post-session.sh
line 1: ACCEPTED  repo:demo ci_runner = "ubuntu-latest"  (authority=medium)
line 2: malformed proposal: expected ident at line 1 column 2
captured 2 proposal(s): 1 accepted, 0 contested, 0 rejected, 1 invalid
consumed .dent8/proposals.jsonl (kept 1 failed proposal line(s) for inspection/retry)

$ cat .dent8/proposals.jsonl
this line is not valid json
```

### `sync-agents-md.sh` — one file, many tools

Injects (or refreshes) a `<!-- dent8:begin -->` … `<!-- dent8:end -->` managed block containing
`dent8 context` output into a static instructions file. `AGENTS.md` is honored by Codex,
Cursor, Windsurf, Cline, Zed, and aider, so a single managed block reaches all of them — the
highest-leverage universal context target. The target defaults to `AGENTS.md`; override it with
the first argument (e.g. a Cursor rule file — see the [Cursor adapter](../cursor/)):

```sh
./sync-agents-md.sh                      # writes/refreshes AGENTS.md
./sync-agents-md.sh .cursor/rules/dent8.mdc
```

It is **idempotent**: run it repeatedly and the block is replaced in place, never duplicated;
prose outside the markers is preserved; a missing file or block is created. Verified locally by
running it twice against an `AGENTS.md` that already carried human prose — exactly one marker
pair remained and the only change between runs was the regenerated timestamp:

```text
$ grep -c 'dent8:begin' AGENTS.md   # after two runs
1
$ diff run2.md AGENTS.md            # third run vs second
11c11
< <!-- generated by `dent8 context` at 1783602147469; regenerate instead of hand-editing -->
---
> <!-- generated by `dent8 context` at 1783602164171; regenerate instead of hand-editing -->
```

The human `# Demo project` heading and `- Keep commits focused.` bullet outside the block
survived every run untouched.

## Wire it into a framework

The pattern is the same everywhere: **context in before the model runs, capture out after.**

- **Context in.** Run `pre-session.sh` at session start and feed its stdout into the agent's
  system message / prompt. If your framework reads a static instructions file instead of taking
  piped context, run `sync-agents-md.sh` so the file carries a fresh managed block.
- **Capture out.** Run `post-session.sh` at session end (or after each turn) to flush queued
  proposals. Where the framework has a real lifecycle hook (Claude Code `SessionEnd`, Cursor
  `stop`), bind it there; otherwise wrap the tool invocation in a shell script that runs it.

### Worked example: aider (no hooks, no MCP)

aider has [no MCP support and no lifecycle hooks](https://github.com/Aider-AI/aider/issues/4506)
as of mid-2026, so it uses the static-file path for context and a wrapper for capture.

1. **Context in** — regenerate a context file and auto-load it every session. Either point
   aider's `read:` at `AGENTS.md` (which `sync-agents-md.sh` maintains) or at a dedicated file:

   ```sh
   ./pre-session.sh > dent8-context.md   # or: ./sync-agents-md.sh AGENTS.md
   ```

   `.aider.conf.yml`:

   ```yaml
   read: [AGENTS.md, dent8-context.md]
   ```

   aider loads `read:` files as read-only context every session
   ([aider config docs](https://aider.chat/docs/config/aider_conf.html)).

2. **Capture out** — a thin wrapper that runs aider, then flushes the queue:

   ```sh
   #!/usr/bin/env sh
   ./pre-session.sh > dent8-context.md   # freshen context before the session
   aider "$@"                            # run the session
   ./post-session.sh                     # flush any queued proposals through the firewall
   ```

The context-injection half is exercisable today (both scripts above were run locally); aider
actually consuming `read:`/the wrapper is per aider's docs and not exercised in this repo.

## Why this is a seatbelt, not the boundary

These scripts sit *around* an agent; they do not replace the firewall. The integrity boundary
remains the event-sourced store plus the MCP/CLI write path (see the
[top-level agent-hooks README](../README.md) and [agent-adapters.md](../../../docs/agent-adapters.md)).
For a framework that speaks MCP, prefer wiring the [`dent8 mcp serve`](../../mcp/) server —
see [connect any MCP client](../../../docs/mcp-clients.md) — which gives live, tool-mediated
fact access instead of a static pack. Use these scripts when a framework has no MCP client and
no native hooks, or alongside MCP to keep a static instructions file fresh.
